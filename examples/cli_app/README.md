# CLI Test Application

Интерактивное консольное приложение для тестирования всех возможностей Megaplan SDK.

## Возможности

- ✅ Авторизация по username/password
- ✅ **Tasks (Задачи)** - полная поддержка:
  - Список, поиск, создание, итерация
  - **🆕 get_full_details() - получение задачи со всеми связанными данными:**
    - Подзадачи и актуальные подзадачи
    - Комментарии и история изменений
    - Аудиторы, соисполнители, вехи
    - Полные данные ответственного и постановщика
    - Гибкая настройка загружаемых данных
  - Управление участниками (auditors, executors)
  - Управление вехами (milestones)
  - История изменений с поиском
- ✅ **Projects (Проекты)** - полная поддержка:
  - Список, поиск, создание
  - **🆕 get_full_details() - получение проекта со всеми связанными данными:**
    - Связанные сделки
    - Задачи проекта и актуальные задачи
    - Комментарии и история изменений
    - Аудиторы, соисполнители, вехи
    - Полные данные ответственного и владельца
  - Управление участниками (auditors, executors)
  - Управление вехами (milestones)
  - История изменений с поиском
- ✅ **Deals (Сделки)** - полная поддержка:
  - Список, поиск, создание
  - **🆕 get_full_details() - получение сделки со всеми связанными данными:**
    - Комментарии, история изменений, история статусов
    - Аудиторы и связанные задачи
    - Полные данные ответственного и контрагента
  - Управление наблюдателями (auditors)
  - История изменений с поиском
- ✅ Comments (Комментарии) - список, создание
- ✅ Contractors (Контрагенты) - список, поиск, создание компаний
- ✅ Employees (Сотрудники) - список, текущий пользователь, поиск
- ✅ Files (Файлы) - загрузка файлов
- ✅ **🆕 Кэширование информации о пользователях:**
  - Автоматическое кэширование данных сотрудников для минимизации API запросов
  - Умное отображение ФИО, должности и ID пользователей во всех разделах
  - Статистика использования кэша (hit rate, размер)
  - Возможность очистки кэша

## Установка

### Вариант 1: Локальная разработка

```bash
# Из корня проекта megaplan-sdk
cd examples/cli_app

# Установить SDK из parent directory
pip install -e ../../

# Запустить приложение
python main.py
```

### Вариант 2: Из PyPI (когда опубликован)

```bash
pip install -r requirements.txt
python main.py
```

## Использование

### Интерактивный режим

Просто запустите приложение:

```bash
python main.py
```

Программа попросит ввести:
- **Base URL**: https://yourcompany.megaplan.ru
- **Username**: ваш email
- **Password**: ваш пароль

### Переменные окружения

Можно создать `.env` файл (скопируйте `.env.example`):

```bash
cp .env.example .env
# Отредактируйте .env
```

Затем запустите с загрузкой переменных:

```bash
# Установите python-dotenv
pip install python-dotenv

# В начале main.py добавьте:
# from dotenv import load_dotenv
# load_dotenv()
```

## Примеры использования

### 🆕 Получение полной информации о задаче (get_full_details)

Самая мощная функция для работы с задачами - получение всех связанных данных за один вызов:

1. Запустите приложение
2. Выберите `[1] Tasks (Задачи)`
3. Выберите `[3] 🆕 Полная информация о задаче (get_full_details)`
4. Введите ID задачи
5. Выберите режим загрузки:
   - `[1]` - Только основная информация
   - `[2]` - С комментариями и историей
   - `[3]` - Полная информация (все данные)
   - `[4]` - Настроить вручную (выборочная загрузка)

**Что вы получите:**
- Основную задачу с полями (ID, название, статус, deadline, ответственный)
- Полные данные ответственного и постановщика (ФИО, email, должность)
- Подзадачи с их статусами
- Последние комментарии
- Историю изменений
- Аудиторов, соисполнителей, вехи

**Пример вывода:**
```

----------------------------------------------------------------------
  ID: 123
  Название: Реализовать новую функцию
  Статус: in_progress

  Имя: Иван Петров
```

### 🆕 Получение полной информации о проекте

1. Выберите `[2] Projects (Проекты)`
2. Выберите `[3] 🆕 Полная информация о проекте (get_full_details)`
3. Введите ID проекта
4. Выберите режим:
   - `[1]` - Только основной проект
   - `[2]` - С сделками и задачами
   - `[3]` - Полная информация

**Что вы получите:**
- Связанные сделки проекта
- Все задачи проекта и актуальные задачи
- Комментарии, историю, аудиторов
- Полные данные ответственного и владельца

### 🆕 Получение полной информации о сделке

1. Выберите `[3] Deals (Сделки)`
2. Выберите `[3] 🆕 Полная информация о сделке (get_full_details)`
3. Введите ID сделки
4. Выберите режим загрузки

**Что вы получите:**
- Историю изменений статусов сделки
- Полные данные контрагента (название, тип, контакты)
- Связанные задачи по сделке
- Комментарии и общую историю

### Создание задачи

1. Запустите приложение
2. Выберите `[1] Tasks (Задачи)`
3. Выберите `[4] Создать тестовую задачу`
4. Введите название или нажмите Enter для дефолтного
5. Задача будет создана и отобразится её ID

### Загрузка файла

1. Выберите `[7] Files (Файлы)`
2. Выберите `[1] Загрузить файл`
3. Введите полный путь к файлу (например, `/Users/user/Documents/test.pdf`)
4. Файл будет загружен и отобразится его ID

### Поиск сотрудника

1. Выберите `[6] Employees (Сотрудники)`
2. Выберите `[3] Поиск сотрудника`
3. Введите имя или email
4. Отобразятся все совпадения

## Troubleshooting

### Ошибка авторизации

```
❌ Ошибка подключения: Authentication failed
```

**Решение:**
- Проверьте правильность username и password
- Убедитесь, что URL начинается с `https://`
- Проверьте доступность сервера Megaplan

### Ошибка SSL

```
❌ Ошибка: SSL verification failed
```

**Решение:**
- Убедитесь, что используете HTTPS URL
- Проверьте сертификат сервера
- Для dev/test можно использовать `allow_http=True` (небезопасно!)

### Ошибка "File not found"

```
❌ Файл не найден
```

**Решение:**
- Используйте абсолютный путь к файлу
- Проверьте существование файла
- Убедитесь, что файл не является директорией

## Кэширование пользователей

CLI приложение автоматически кэширует информацию о пользователях для оптимизации производительности.

### Как это работает

1. **Автоматическое кэширование**: При первом запросе информации о пользователе данные загружаются из API и сохраняются в памяти
2. **Повторное использование**: Все последующие запросы к тому же пользователю берутся из кэша без обращения к API
3. **Умное отображение**: Везде где показываются пользователи (ответственные, авторы комментариев, аудиторы), вы видите:
   - Полное ФИО
   - Должность (если указана)
   - ID в скобках

### Просмотр статистики кэша

В главном меню выберите `[c] 📊 Статистика кэша пользователей`:

```
📊 Статистика кэша пользователей:
----------------------------------------------------------------------
  Размер кэша: 15 пользователей
  Попаданий в кэш: 247
  Промахов: 15
  Hit rate: 94.3%
----------------------------------------------------------------------
```

**Показатели:**
- **Размер кэша**: Количество уникальных пользователей в кэше
- **Попадания в кэш**: Сколько раз данные были получены из кэша (без API запроса)
- **Промахи**: Сколько раз потребовалась загрузка из API
- **Hit rate**: Процент попаданий в кэш (чем выше, тем эффективнее)

### Очистка кэша

В главном меню выберите `[x] 🗑️  Очистить кэш пользователей` если нужно:
- Освободить память
- Обновить данные пользователей (если они изменились в системе)
- Сбросить статистику

### Преимущества кэширования

- **Скорость**: Мгновенное отображение информации о пользователях
- **Экономия**: Минимизация запросов к API Megaplan
- **Удобство**: Читаемые ФИО вместо ID во всех местах
- **Эффективность**: Hit rate обычно >90% при работе с задачами/комментариями одной команды
