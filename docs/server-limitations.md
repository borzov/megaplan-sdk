# Особенности API Мегаплана

Наблюдения проверены на рабочем аккаунте 24 ноября 2026 года, если в строке указана более ранняя проверка — использованы результаты предыдущих версий SDK. Доступ к карточке и включение в список зависят от эндпоинта, роли и конфигурации аккаунта.

| Операция | Наблюдаемое поведение и способ работы через SDK |
|---|---|
| S1. Сотрудники | Стандартный список отдавал работающих. Для остальных сервер перечисляет фильтр `not_working` в `employeeFilter`. Используйте `employees.iterate(include_dismissed=True)` для обхода обеих выборок. В проверке получилось 27 текущих и 31 уволенный. Произвольный термин по фамилии пропустил заведомо отсутствующее значение, свободный q дал ноль даже на известной фамилии. |
| S2. Поиск задач | Отрицательный контроль сработал для `name` и `statement`. Сервер проигнорировал аналогичное условие по `description`, `textStatement` и `subject`. При составлении произвольного FilterBuilder сравнивайте выдачу для известного и отсутствующего значения. Список полей для чтения отличается от списка полей для поиска. В архивном поиске по двум полям сервер принял единую группу OR с маркером архива и обоими текстовыми терминами. Вложенная группа в terms дала 422. |
| S3. Комментарии | Список и карточка принимают fields в JSON-литерале запроса. Используйте `raw("GET", path, query={"fields": ["workTime", "content"]})`. Поле чтения трудозатрат называется workTime. У аргумента `comments.create(work=2.5)` единица измерения — час. |
| S4. Удаление комментария | По данным предыдущей проверки сервер может ответить 403 даже автору. SDK передаёт AuthorizationError. При подготовке 0.8.0 удаления в боевом аккаунте не выполнялись. |
| S5. Вехи | Общий GET /milestone дал 405, GET /deal/{id}/milestones существующей сделки — 404. Получите связанные задачи через deals.get_linked_tasks(), затем их вехи через tasks.get_milestones(). Для проекта используйте projects.get_milestones(). |
| S6. Текущий сотрудник | employees.get_current() использует /currentUser. Для employees.get("me") SDK выдаёт подсказку до запроса к /employee/me. |
| S7. Повторные ссылки | Сервер может опустить имя при повторной ссылке на сущность. SDK заполняет пропуски из полных ссылок того же ответа. При необходимости получить связанную карточку используйте expand. |
| S8. Поиск контрагентов | Подтипный маршрут поиска может вернуть Company и Human. Абстрактный /contractor/search в прежних проверках дал 500. Текстовый поиск может пропустить точное совпадение по ИНН вне названия компании. В проверке пагинации поиска следующая страница содержала уже виденные ссылки. Полнота iterate_search на этом аккаунте не подтверждена. |
| S9. История и дела контрагента | В предыдущих проверках работали подтипные маршруты /contractorCompany или /contractorHuman. Передайте известный content_type в ресурс, чтобы избежать лишнего чтения карточки. |
| S10. Массовое чтение ссылок | getEntitiesByLinks принимает массив ссылок, может менять порядок и пропускать недоступные записи. Пачка из 25 ссылок прошла проверку. Для Employee SDK обращается к отдельным карточкам. missing означает отсутствие в ответе. |
| S11. Обновление токена | Сервер ротирует refresh token. SDK обновляет пару в памяти, приложение может сохранять её через on_token_refresh. Для бинарного потока действует заблаговременное обновление токена. При полученном 401 открытый поток автоматически не воспроизводится. |
| S12. Вложения | Загрузка отправляет multipart files[] на /api/file. Для скачивания по доступному пути используйте attachments.download или attachments.stream. |
| S13. Demo и рабочий аккаунт | Наличие space/* или automation/* в demo-RAML само по себе не подтверждает доступность конкретного метода для рабочей роли. Для этих семейств в аудите 0.8.0 не было проверенного прикладного сценария. |

## Архив задач

Без фильтра сервер вернул 256 записей. При include_archive=True два полных прохода с разной сортировкой дали 5 919 уникальных пар (тип, ID). Фильтрация по statuses на сервере совпала с локальным отбором completed, accepted и cancelled. Три карточки из предыдущей проверки открывались по ID и при поиске по названию, хотя в общем архивном обходе отсутствовали. Архивный list удаляет повторы внутри страницы, поэтому по её длине нельзя определять конец обхода. Для полной последовательности используйте iterate. Метод find_missing_in_archive сверяет только переданные ссылки. Причина расхождения общего списка с карточками не установлена.

## Реквизиты

На аккаунте встречаются Legal и Natural, состав полей зависит от страны и типа. В 0.7.0 на специально созданных объектах проверены сохранность незаданных полей, очистка bank, одно кастомное поле и замена contactInfo. Между последним GET и POST в apply_update возможно изменение через другой клиент. После конфликта заново получите preview и сверьте diff. Совпадение значения в карточке не устанавливает автора предыдущей записи.

| Поля плательщика | Результат проверки частичного обновления |
|---|---|
| `bank` | В октябре 2026 проверена очистка пустой строкой и null. Обновление соседнего реквизита сохранило банк и название. |
| `inn`, `kpp`, `ogrn`, `okpo` | Поочерёдное изменение и восстановление каждого поля для применимых типов Legal и Natural ожидает прогона на выделенном стенде. |
| `bik`, `correspondentAccount`, `currentAccount` | Ожидает того же прогона для банковских реквизитов. |
| `address`, `legalAddress` | Ожидает того же прогона для адресов. |
| `…FioPodpisanta`, `…DolzhnostPodpisanta`, `…NaOsnovanii` | Октябрьская проверка одного кастомного поля не устанавливает результат для каждого из трёх полей подписанта. Доступность определяется настройками стенда. |

Для повторения проверки см. [сценарий записи](../scripts/README.md#verify_contractor_writespy).
